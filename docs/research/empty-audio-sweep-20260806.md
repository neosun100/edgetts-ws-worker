# 全音色空音频普查（2026-08-06）

用 v2.23.0 上线的结构化日志作为观测手段，对生产 `https://edgetts.aws.xin` 做了两轮实测，
共约 **420 次真实上游调用**。

起因：v2.24.0 修掉「上游返回 200 + 0 字节被透传成成功」后，需要回答两个问题 ——
**(A) 有没有音色连自己语种都合成不出来？(B)「零覆盖」的规律到底是什么？**

---

## 结论速览

| 问题 | 答案 |
|---|---|
| 有音色对自己语种失效吗？ | **没有。322/322 全部返回非零音频。** |
| 空音频的规律？ | **文本书写系统 ≠ 音色书写系统 → 空音频。** 62/90 交叉组合命中，同书写系统 0 失败 |
| 例外 | **拉丁文本对所有音色都有输出**；**Multilingual 音色对所有书写系统都有输出**（9/9） |
| 陷阱 | 希腊文送非希腊音色**不是空音频，而是错误音频** —— 现有 502 拦不住（见下） |

---

## A) 母语普查：322 个音色 × 自身语种文本

**全部通过。** 322/322 返回 `200` + 非零字节。

| 指标 | 值 |
|---|---|
| 延迟 | 中位 **230ms**，p95 602ms，最大 1974ms |
| 音频字节 | 中位 20448，范围 14256–35568 |
| 探测文本 | 117 个音色用其语言的母语文本，205 个（拉丁语系）用英文 |

结论：**没有「坏音色」。** 上游对全部 322 个音色都能正常合成，前提是给对文字。

### 这一轮我先得出了错误结论，值得记下来

第一版普查报告 **30/322 失败**，涉及 `bn gu kn ml si ta te`（Indic）、`km lo my`（东南亚）、
`he`（希伯来）。看着像重大发现。

**实际是我的探针错了。** 我把这些语言按「书写系统组」归类，给整组发同一段文本：

| 我的分组 | 我发的文字 | 组内实际情况 |
|---|---|---|
| `Indic` | 天城文（Devanagari） | 只有 hi/mr/ne 用天城文；bn/gu/kn/ml/si/ta/te **各有自己的字母** |
| `SEAsian` | 泰文 | 只有 th 用泰文；km/lo/my 各自不同 |
| `RTL` | 阿拉伯字母 | ar/fa/ur/ps 用阿拉伯字母；he 用希伯来字母 |

失败集合与「我发错文字的语言集合」**完全重合**，无一例外 —— 这个完美相关性本身就是探针有错
的信号。改成**按语言**给母语文本后，异常从 30 变成 **0**。

所以那 30 个「失败」其实是 **30 次「新 502 正常工作」的确认**。

**教训：分组前先确认组内成员真的共用同一套字母。** 以及：当失败集合与自己某个实现选择完美
相关时，先怀疑探针。

## B) 交叉矩阵：9 种书写系统的音色 × 9 种书写系统的文本

`O` = 有音频，`X` = 空音频（现返回 502 `upstream_empty_audio`）

| 音色 \ 文本 | Latin | CJK | Arabic | Hebrew | Devanagari | Tamil | Thai | Cyrillic | Greek |
|---|---|---|---|---|---|---|---|---|---|
| **Latin** (en-US-Ava) | O | X | X | X | X | X | X | X | O |
| **CJK** (zh-CN-Xiaoxiao) | O | O | X | X | X | X | X | X | O |
| **Arabic** (ar-EG-Salma) | O | X | O | X | X | X | X | X | X |
| **Hebrew** (he-IL-Hila) | O | X | X | O | X | X | X | X | X |
| **Devanagari** (hi-IN-Swara) | O | X | X | X | O | X | X | X | X |
| **Tamil** (ta-IN-Pallavi) | O | X | X | X | X | O | X | X | X |
| **Thai** (th-TH-Premwadee) | O | X | X | X | X | X | O | X | X |
| **Cyrillic** (ru-RU-Svetlana) | O | X | X | X | X | X | X | O | X |
| **Greek** (el-GR-Athina) | O | X | X | X | X | X | X | X | O |
| **Multilingual** (en-US-AvaMultilingual) | O | O | O | O | O | O | O | O | O |

**矩阵是对角的**，加两列/一行全 O：

1. **Latin 列全 O** —— 任何音色都能读拉丁字母（发音可能怪，但有输出）。
2. **Multilingual 行全 O** —— 12 个 Multilingual 音色是通吃的（9/9 书写系统）。
3. **Greek 列有 3 个 O** —— 见下方陷阱。

同书写系统失败数：**0**。跨书写系统失败：**62/62**（除上述例外）。

## ⚠️ 现有 502 拦不住的情形：非空但错误的音频

Greek 列打破了对角规律，查下去发现它**不是「零覆盖」，而是「念错了」**。
同一段希腊文 `Γεια σας, αυτή είναι μια δοκιμαστική πρόταση.`：

| 音色 | 字节 | 时长 | 实际发生什么 |
|---|---|---|---|
| `el-GR-AthinaNeural`（母语） | 19584 | **3.26s** | 正常朗读 |
| `en-US-AvaNeural` | 66240 | **11.04s** | 逐个念**字母名**（"gamma epsilon iota..."），比正常长 3.4 倍 |
| `zh-CN-XiaoxiaoNeural` | 10656 | **1.78s** | 大部分被跳过，只剩零星发音 |

**这是 `upstream_empty_audio` 覆盖不到的类别**：字节数非零，所以 502 不触发，调用方拿到的是
一段听起来不对的音频。

**当前判定：不额外拦。** 理由：
- 判断「音频内容是否正确」需要时长/文本长度比之类的启发式，误伤风险高（正常朗读的语速本就
  因语种和 `speed` 参数差异很大）。
- 与空音频不同，**这种情况用户听一遍就知道**，不是静默失败。
- 真正的出路是文档与 UI 引导（用对应语种音色，或 Multilingual 音色），而不是服务端猜测。

已写进双语 README 的音色选择建议。

## 对产品的直接影响

1. **`upstream_empty_audio`（v2.24.0）覆盖了 62/90 的跨书写系统组合** —— 这些此前全都是
   「200 + 空音频」的静默成功。修得对。
2. **Multilingual 音色是跨语种场景的正解**：12 个音色对 9 种书写系统全部有输出。
   这一点值得在 UI 的音色选择器里更显眼（当前有「仅多语言」筛选，但没解释它为什么重要）。
3. **不需要维护「坏音色黑名单」** —— 322 个音色对自己语种都是好的，问题只出在文本与音色的
   配对上，那是调用方可控的。

## 复现方式

```bash
# 音色列表
curl -s https://edgetts.aws.xin/v1/models/public -o /tmp/voices.json

# A) 母语普查(322 次,约 3 分钟,并发 5)
EDGETTS_KEY=... node scripts/research/sweep.mjs native   # -> /tmp/native.json

# B) 交叉矩阵(90 次)
EDGETTS_KEY=... node scripts/research/sweep.mjs cross    # -> /tmp/cross.json
```

探针脚本：`scripts/research/sweep.mjs`（并发 5，避免打爆上游）。
