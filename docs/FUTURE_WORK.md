## 为什么单开这一份

`ROADMAP.md` 的 P0/P1/P2 都已关闭，它现在是一份**历史记录**。而下面这些东西不属于
「待办」（没人要求做）、也不属于「刻意不做」（没被永久否决），它们是第三类：

> **已经看见了，评估过了，判断现在动的收益配不上风险 —— 但将来条件变了可能值得。**

这类东西如果不写下来，两种结局都不好：要么被遗忘，要么被下一个 Agent 当成新发现的
bug 重新提出来、重新调查一遍（本项目已经因此浪费过时间，见 HANDOFF §9 的方法论一节）。

## 一、最值得做的一条：看真实流量数据（**不需要写代码**）

**这是唯一一条我会主动推荐的**，因为它是「看」而不是「改」，零风险。

结构化日志（P1-6）从 2026-08-06 起上线，到现在积累了三天多。查询方式见 HANDOFF §7。
它能回答三个此前**没有分母**的问题：

| 问题 | 为什么值得问 | 可能的结论 |
|---|---|---|
| 322 个音色的语言映射表还值得维护吗？ | `ui/index.html` 里那张表是 2463 行的主要构成之一 | 若 99% 请求集中在 10 个音色，那张表就是**负债**，抽离或裁剪才有依据 |
| `MAX_CHUNKS=45` 与默认 `chunk_size=300` 合理吗？ | 实测默认值容量是 12179–13500 字符 | 若真实输入普遍远短于此，默认值可以调小以降低首字节延迟 |
| 重试率与 5xx 率是多少？ | 上线前这两个数**根本没有分母** | 若重试率显著，说明上游抖动比预估严重，值得调 `getAudioChunk` 的退避策略 |

**本项目最硬的一条经验**：**没量之前，「该改」和「不值得改」长得一模一样。**
本轮每个"可能有问题"的猜测被量化后，一半变成了确实是缺陷（并发栅栏 2.5×、token 归因、
UI 邻近性），另一半变成了不值得做（MP3 帧级拼接）。

⚠️ **查日志的坑**（踩过）：`wrangler tail --format=json` 的输出是「多个 pretty-print
JSON 对象首尾相接」，**不是 JSONL**。按行解析会得到 0 条，要按大括号配平切分。

## 二、已知但判断不值得动的（按「动的风险」从低到高）

### 2.1 `?neural` 参数是恒定 no-op（保留是为了兼容）

`filterModels()`（`src/worker.js:710`）支持 `?neural=true`，但上游 **322 个音色全部**
含 "Neural" 字样，所以这个参数**永远不过滤掉任何东西**。2026-08-09 实测复核：
不带参数 322 条、`?neural=true` 322 条。

- **为什么保留**：去掉会让既有调用方的 `?neural=true` 请求行为改变（虽然结果一样，
  但契约变了）。代码里已有注释标明它无实际作用。
- **将来若要动**：只有在明确知道没有调用方依赖它时才移除。**不要**在它之上做新设计。

### 2.2 `CHANGELOG.md` 有两个 `## [2.22.0]` 标题

`CHANGELOG.md:606` 和 `:660` 都是 `## [2.22.0] - 2026-08-06`，内容不同（一条讲部署路径
修复、一条讲别的）。这是当时手写 CHANGELOG 的笔误。

- **为什么现在不动**：版本一致性测试用 `/^##\s*\[(\d+\.\d+\.\d+)\]/m` 只取**第一个**
  标题（`test/unit/pure-helpers.test.mjs:305`），而重复的两个都在文件深处，
  **不影响任何测试、不影响任何读者的判断**。
- **将来若要动**：把第二个改成它实际对应的版本号（需要查 git log 确认那批改动的真实归属），
  或合并成一个条目。属于纯整理，无风险但也无收益。

### 2.3 `// @ts-check` + JSDoc（原 ROADMAP P2 / HANDOFF TODO-1）

给 `src/worker.js` 顶部加 `// @ts-check`，逐步补 JSDoc。**不引入 TypeScript、不改构建、
不改运行时。**

- **收益**：能在编辑器里抓到 `undefined` 传参、拼错的属性名。本项目修过的 bug 里有这类
  （`parseWebmChunk` 返回的字段叫 `tc` 而非 `timecode`，我审计时就猜错过）。
- **为什么不做**：纯内部收益、用户零可见；而 `src/worker.js` 刚经过契约审计
  （7 模块 250 用例）、覆盖率 99.47%。**现在动它是拿已验证的稳定性换抽象的「更严谨」。**
- **若一定要做**：一次只加一个函数的 JSDoc，每次跑 `npm test`。别一把全加。

### 2.4 前端拆分（原 ROADMAP P2 / HANDOFF TODO-2）—— **最不建议**

`ui/index.html` 已 2463 行（866 CSS + 1328 JS + HTML），含 322 个音色的语言映射表。

- **为什么最不建议**：
  1. 用户零可见收益
  2. 它刚经过系统审计（7 个方向，1 真缺陷已修），有 21 项 browser e2e 守着
  3. **会撞上 HANDOFF §6.1 那个硬约束**：内联 `<script>` 里不能有反引号或 `${`
     （构建会把 UI 塞进 Worker 的模板字符串），且 `scripts/build.mjs` 要跟着改
- **前置条件**：先做上面第一条（看流量数据）。**如果数据显示 99% 请求集中在少数音色，
  那张表就该裁剪而不是搬家** —— 那时拆分的动机才成立。
- **若一定要做**：先只抽「音色语言映射表」这一块**纯数据**，别动逻辑；抽完立刻跑
  `npm test` 确认 21 项 browser e2e 全过。

## 三、观察到但**明确不构成问题**的（记下来免得重复调查）

这一节的价值是**防止重复劳动**。以下每条都被我实际查证过，结论是「没问题」。
如果你（Agent 或人）觉得它们看着可疑 —— 是的，我也觉得，所以查了。

| 观察 | 看着可疑的地方 | 实际结论 |
|---|---|---|
| `MODELS_CREATED_AT = 1754265600` | 硬编码时间戳，注释写 `2025-08-04` 而项目是 2026 年 | **注释正确**，实测该秒值确为 `2025-08-04T00:00:00Z`。刻意用固定值而非 `Date.now()`：否则 322 条每次都不同 → 响应体逐字节不同 → ETag 无从稳定、CF 边缘无法复用 |
| `suggestChunkSize()` 的 `while (lo <= hi)` | 生产代码里的无界 while 循环 | **有界**：标准二分，`lo`/`hi` 每轮必收敛，最多 ~11 次迭代。且只在**已经要返回 413** 的路径上跑 |
| `tokenInfo.expiredAt &&` 这个判断 | 行为上冗余（`n < null` 本就是 false），变异测试会报「存活的变异体」 | **刻意保留**：这是**等价变异体**而非覆盖率缺口。留着让「两个字段都必须有值」这个意图显式可读，而不是依赖类型强转规则。`src/worker.js:1339-1342` 有注释说明 |
| `remove_emoji` 不删 `©` / `™` | 它们 `Extended_Pictographic=true`，看着像漏删 | **刻意的**：它们是正常文本，「©2026」念成「2026」是另一种数据损坏。用 `\p{Extended_Pictographic}️`（带 VS16）限定，只命中「明确要当 emoji 显示」的 |
| `__init__ 方法` 仍被当粗体去掉下划线 | 看着是 `remove_markdown` 的 bug | **markdown 固有歧义**，不可修：`__init__`（前后空格）与真粗体 `__粗体__` 在语法上无法区分，CommonMark 也这么判。同理 `*.txt 和 *.md` |
| 希腊文送非希腊音色 | 返回的音频内容是错的（逐个念字母名，时长 3.4 倍） | **刻意不拦**：这不是空音频（502 拦不住），判断「内容是否正确」需要启发式，误伤风险高；且与空音频不同，用户听一遍就知道。见 HANDOFF §5 |
